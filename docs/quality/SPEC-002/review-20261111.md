# SPEC-002 架构与对抗性评审记录（2026-11-11）

## 评审方式

两个独立只读评审上下文：

- **架构评审**：核查独立 module 可行性、`collect` 抽取、薄包装/类型别名、API 零值语义、目录聚合、CI/验收、性能预算，以及与现有代码的事实一致性。
- **对抗性评审**：攻击无状态/只读、JSON 契约、`match.status` 状态机、错误码、凭据泄露、迁移回归、验收可绕过和已知限制，并要求给出具体反例。

两份评审均未修改仓库；关键结论由主会话对照 `internal/parser`、`internal/scanner`、`internal/probe`、`internal/tmdb`、`internal/matcher`、`internal/store`、`cmd/mstruct` 和 `docs/quality/SPEC-001/rollout0-calibration.md` 复核。

## 已修复的 high 项

- 类型别名必须是真正的 `=` 别名；测试、`testdata/filenames.txt` 和未导出符号测试随实现迁入模块。
- `--tmdb-base-url`/`TMDBOptions.HTTPClient` 支持 mock 和零请求断言；G6 增加 `cmd/mstruct` 临时目录/SQLite 断言，不再逐字节比较随机输出。
- context 取消优先返回 `ERR_CANCELED`；`collect` 每个目录项/探测前检查；stdout 先序列化再一次写入。
- TMDB 重试对齐 SPEC-001（429 1s→60s×5，不可达 2s→30s×3，单请求 10s，单组 60s deadline）；`probe` 两工具共享 10s 总预算。
- 匹配后按 `best.Movie.ID` union；空 `GroupKey` 用文件路径生成内部组键。
- `tmdb` 所有错误路径不输出 URL query/API key/响应 body；`--tmdb-base-url` 仅用于测试。
- 定义 `ok=false` 最小错误对象、数组空值 `[]`、可空标量 `null`、无候选 `margin=null`。
- LLM 缺 key 降级为 `match.llm_key_missing` warning；resolver 运行时失败为 `match.llm_unavailable`。
- Warning 触发/聚合/排序写死；`match.partial` 接入多组部分失败路径。
- G3 明确已知限制桶和含/不含两套准确率；映射契约测试不再冒充真实准确率。
- `--help`/`--version` 作为单对象规则例外；flags 支持路径前后混排。
- 确定性承诺限定为 `--match=off --probe=off`；atime 不在只读保证范围。
- `tmdb` 缓存增加 `CacheLimit`；内存预估限定典型规模。
- 修正 TV 示例年份、`S01E01-E03` 标题残留、CJK 季号、`Show S01` 等已知限制。
